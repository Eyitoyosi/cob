# database-rds

Provisions a managed relational database: encrypted storage, a
security group that accepts connections **only from specified security
groups** (never CIDR blocks), and auto-generated credentials stored in
Secrets Manager — never exposed as a Terraform output. Prod and dev
diverge on operational safety (Multi-AZ, deletion protection, backup
retention), derived automatically from `environment`.

## Usage
    module "orders_db" {
      source                      = "../../modules/database-rds"
      name                         = "orders"
      environment                  = "dev"
      vpc_id                       = module.networking.vpc_id
      database_subnet_group_name   = module.networking.database_subnet_group_name
      allowed_security_group_ids   = [module.ingestion_service.security_group_id]
    }

| vpc_id | string | — | |
| allowed_security_group_ids | list(string) | — | The **only** access-control mechanism — no CIDR option exists |

## Outputs
| Name | Description |
|---|---|
| endpoint | DB address |
| port | |
| security_group_id | |
| secret_arn | Secrets Manager ARN — read credentials via the AWS SDK at runtime, never via `terraform output` |

## Security notes
- Storage is always encrypted; no override.
- Credentials are generated by Terraform but never appear in state
  output or `.tfvars` — only inside the Secrets Manager secret value.
- Prod gets `deletion_protection = true` and a mandatory final
  snapshot; dev intentionally skips both so throwaway databases don't
  block `terraform destroy`.

## Known limitations
- Single-AZ read replica support not yet built.
- No automated credential rotation configured on the Secrets Manager
  secret yet — a reasonable v2 addition.
